# WotR Planner v1 (TypeScript, Solid 2) and its MCP server

Label: wayfinder:map

## Destination

A v1 spec for the TypeScript planner UI and its MCP server, settled enough to hand off: every design question below is decided, recorded in `GLOSSARY.md`, `docs/adr/` and the tickets' answers, and nothing is left to decide before implementation starts.

## Notes

- **Planning only.** Tickets decide; they don't build. Implementation starts after the map is clear.
- **The build:** implementation lives in its own tracker, [wotr-planner-build/plan.md](../wotr-planner-build/plan.md), with tickets 01–06 written on 2026-11-19 (01–05 reach the first usable version). A design question it raises comes back here as a new ticket.
- **Repo and tracker.** This checkout has been a git repo (branch `main`) since 2026-11-19. The tracker is the local markdown one: this map plus one file per ticket in `issues/`. Tickets follow the usual wayfinder workflow: claim, resolve, then a pointer in Decisions so far. Research findings go on a throwaway `research/<name>` branch, and the ticket links to them. The four research tickets started before the repo existed keep their findings in `research/` on `main`.
- **Skills:** grilling tickets call `grilling` and `domain-modeling`. UI code follows `AGENTS.md` (Solid 2, not React or 1.x).
- **Sources of truth:** the BubblePrintsData dump `2.7.0x_0` (the data) and xADDBx/WrathDecompiled at `6ce4a6b` (the behaviour), both git-ignored and fetched at those pins. `decompiled/` is already here; `blueprints/` is not yet. The guide `docs/decompiled-guide.md` is the engine's design (modules P, G, W, S, R, E, C, plus the importer I and the allowlist check A). It is this repo's copy of the Rust planner's guide, rewritten for the game-shaped allowlist importer (ADRs 0004 and 0005), and holds unless a ticket here overrides it.
- **Prior art:** the Rust planner at `~/code/wotr-planner` (its `.scratch/wotr-planner/` map, issues and research). Zoom into it for facts; reuse its terms, not its code. Its game data was extracted from a community guide, so the TypeScript planner does not inherit it.
- **Copyright boundary:** the repo never holds the game's text strings, dump or code. The one exception is blueprints' English display names (ADR 0006); descriptions never. Cite facts by blueprint name and GUID, and rules by file and method with the WrathDecompiled commit.
- **Settled before this map** (grilling session, 2026-11-19):
  - The TypeScript planner replaces the Rust one. Its scope is the guide's Build (race to level 20/40, Mythic rank 10, path switches), with spellbooks only as prerequisite gates. It covers every DLC and prestige class with no gating, and leaves exploits out.
  - Mythic ranks can be placed at any character level, in rank order. The game's rank table only gives each rank's **Expected level**: the default placement and a hint, never a rule (user, 2026-11-19, ADR 0003).
  - Edits go through the walk. A plain edit that breaks a later pick is refused and names that pick. A **Cascade edit** clears what it breaks after a preview, and undo covers it.
  - Gear is one set per Build, checked for item restrictions and proficiency. Gear doesn't meet stat prerequisites unless the Build opts in (ADR 0002), and the MCP never opts in.
  - Summaries are generated from components, with hand-written overrides (ADR 0001). The agent owns the theme, and the server derives mechanical **Synergy links**.
  - The MCP is a `/mcp` endpoint on the same Solid server, sharing the engine with the UI, plus a stdio wrapper. Builds are shared as links that work both ways.

## Decisions so far

- [Reading the dump from TypeScript](issues/02-reading-the-dump-from-typescript.md): the `.binz` is BubblePrints' chunked LZ4-block container. Node streams all 236,660 blueprints with no dependencies in about a second at about 250 MB peak. Read it once and keep what's needed, indexed by GUID; a name maps to a list of GUIDs.
- [Earliest character level for each Mythic rank](issues/05-earliest-level-for-each-mythic-rank.md): the game holds the table itself, in MythicsSettings `3b8a6729da1e13a4e8e606e9f0fa38d8` `CharcaterLevelRestrictions` (levels 6/7/9/11/14/15/16/17/17/19), so it is imported, not kept by hand. The game enforces it only in respec and forced level-ups, so the planner uses it as each rank's Expected level, not as a rule (ADR 0003).
- [Component vocabulary for summaries and synergy links](issues/03-component-vocabulary.md): one reader driven by component types finds every kind of value. 155 component types carry one, 50 of them cover 90% of the facts, and the remaining cost is one label per type saying what it does with the value. Links on ability scores, weapons, schools, energy and descriptors are cheap. Critical hits and flanking need hand-written overrides.
- [Which items the game actually hands out](issues/04-which-items-the-game-hands-out.md): the dump traces 3,397 of 4,542 equipment blueprints to a real source (2,680 without the Midnight Isles), so Gear can be an allowlist of sourced items with a tiny hand-kept list. For a player character, item restrictions come down to no druid levels, a required class or path, an alignment mask and main character only.
- [Whose builds: main character only?](issues/01-whose-builds.md): yes. Every Build is the main character, so the main-character-only item, prerequisite and Trickster waiver rules always apply.
- [Where an MCP Build lives between calls](issues/06-where-an-mcp-build-lives.md): nowhere. The MCP keeps no state: tools take a Build code and return the new one beside structured JSON, and every code is also a Share link.
- [Synergy link kinds in v1](issues/09-synergy-link-kinds.md): only the cheap kinds (prerequisite chain, ability score, weapon, spell school, energy, a short descriptor list). A shared bonus type is a "won't stack" warning. Critical hits, flanking and conditions are dropped as links.
- [How Summaries are generated and overridden](issues/10-generating-summaries.md): v1 labels the top 50 component types (about 90% coverage). A blueprint with nothing labelled shows its prerequisites and grants with "no summary yet". Hand-written summaries live one file per GUID, with a fingerprint the load check verifies.
- [Cascade edits: clear only, or move picks?](issues/11-cascade-clear-or-move.md): always clear, never move. Every kind of edit follows one rule: the walk re-judges the whole Build, and whatever fails is refused (plain edit) or listed and cleared (Cascade edit).
- [Which items count as Gear](issues/12-which-items-count-as-gear.md): the 3,397 sourced items plus a hand-kept list (`colossus-ring` first), with Midnight Isles as a UI filter. Gear is the worn places plus one main hand and one off hand. Usables wait for the sheet.
- [Build code format](issues/07-build-code-format.md): the Rust planner's codec, with the whole Build in `/#b=<code>`: a version byte, a DEFLATE body, and keys as 24-bit FNV-1a hashes of the blueprint GUID, unique within each kind and with aliases for replaced entries.
- [Verification depth in v1](issues/14-verification-depth.md): for now, only the Rust planner's two gold builds (Jack-in-the-Green, the Enforcer), plus unit tests citing the game. There is no generated corpus or K/L/N/X yet.
- [MCP tool surface](issues/08-mcp-tool-surface.md): 14 stateless tools, from `start_build` to `compare`. Cascade is a `mode` on `pick` and `equip`, closed options come back as counts unless asked, there's no whole-build tool, and `sheet` carries only the numbers the walk computes.
- [Engine layout and where the imported data lives](issues/16-engine-layout-and-imported-data.md): the importer writes committed `data/` (one file per GUID), and the walk runs in the browser on one hashed JSON document, with the MCP running the same engine on the server. One package: `engine/` at the repo root (no Solid or `src/` imports, enforced by a scoped `no-restricted-imports` rule, imported through a `~engine/*` alias), `src/routes/`, `tools/importer/`, `data/` (ADR 0004). Amended: the importer is one generic, game-shaped filter over the reachable set, driven by a hand-written, cited allowlist of under ~100 types and checked against the dump, with no C# parser (ADR 0005, with its known costs and mitigations).
- [Hosting](issues/17-hosting.md): the UI is published as a static site on GitHub Pages, with the OGL notice. The MCP stays local (stdio wrapper or `npm start`'s `/mcp`) until someone else needs it.
- [Display names](issues/19-display-names.md): English display names are committed and descriptions never are (ADR 0006). Shared names get a qualifier from the grantor, the prerequisite that tells them apart, or an override. Nameless blueprints are never shown; Refusals word them by the kind of grantor ("a deity that allows it"). Gold builds are converted once into GUID-keyed fixtures.
- [Nested prerequisite conditions](issues/20-nested-prerequisite-conditions.md): `PrerequisiteCondition` holds an And/Or/Not condition tree. P reads it as one leaf whose named thing is the tree; the walk and R evaluate it, and G sees every fact in it. The prerequisite list stays flat.
- [Story-state prerequisites](issues/21-story-state-prerequisites.md): etude, companion and campaign checks are always met, as path unlocks are; a Refusal never cites story state.
- [Feats whose parameter is a spell](issues/22-spell-parametrized-feats.md): the 94 spell-parametrized feats stay out of v1 until phase 2 brings spells. The importer's report lists them.
- [Grants carried by buffs and action trees](issues/23-grants-carried-by-buffs-and-actions.md): `data/` holds the buffs that carry grants of held features, with only their grant parts, and `AddFactContextActions`' grant actions with their conditions, so G sees the composite blasts and Magical Tail's ranks.
- [The wandering spirit is a daily choice](issues/24-wandering-spirit-is-a-daily-choice.md): not part of a Build, and neither is any other pick made through an ability (hexes, minor spirits, mythic tricks, Mixed Bloodline). A leaf that needs one of their options is met while the character holds the ability's feature.
- [Features only the story grants](issues/25-story-granted-features.md): out of scope; no Build holds them, and a leaf that needs one is unmet.
- [Mixed Bloodline is a daily choice](issues/26-mixed-bloodline-is-a-daily-choice.md): the Mixed-Blooded Bloodrager's bloodline picks, made through an ability whose resource refills on rest, are daily, not part of a Build.
- [Qualifying shared names, blueprint by blueprint](issues/27-qualifying-shared-names-per-blueprint.md): each blueprint in a shared-name group takes its nearest named grantor, then grantor and level, then kind, then prerequisite, then a `"change": "name"` override. This amends ticket 19's order (ADR 0006, amended). Amended 2026-11-20: a blueprint the game hides (`HideInUI`) is never shown, like a nameless one, so it joins no group; items reached only as Gear wait for [Telling Gear items apart](issues/29-telling-gear-items-apart.md).
- [Facts the character-creation unit grants](issues/28-facts-the-chargen-unit-grants.md): every Build holds what `BlueprintRoot.m_DefaultPlayerCharacter`'s `AddFacts` gives, from level 0, so the deities that forbid `ForbiddenDeityFeature` are refused.
- [Path switches in detail](issues/31-path-switches-in-detail.md): a switch is the rank's class in a Build's ranks. Gold Dragon and Swarm That Walks are ported from `ReplaceAllMythicLevelsWithMythicHeroLevels`. Devil and Legend keep picks per the user's account (Legend Mythic levels 1–2, Devil 1–7). The details come from GameFAQs and the Rust planner, checked against the data. Dropped picks count until the switch. Every switch, Legend included, is taken at rank 8 (note, 2026-11-21).
- [Shifter aspects kept on](issues/32-aspects-kept-on.md): a Build lists the aspect toggles it keeps on, judged at every level against the group size (1 plus each held `IncreaseActivatableAbilityGroupSize`). Only the listed toggles' buffs count as on. As built: `BuffExtraEffects.m_CheckedBuffList` isn't kept, since no kept component sets it (a `holds` check guards that), and the Shifter aspect group's size is 1.
- [Telling Gear items apart](issues/29-telling-gear-items-apart.md): items sharing a name are told apart by, in order, collapsing identical twins into one choice, the required Mythic path or class ("The Bound of Possibility (Aeon)"), the item's own numbers (enhancement, slot, type), then an override. Coordinator, on the user's standing instruction; built by build ticket 02f. Amended (user, after the 02+03 review): Finnean's stages are separate choices, and twins are derived at load, not stored; build ticket 02g.
- [A better automatic qualifier when a blueprint has several grantors](issues/30-qualifier-for-several-grantors.md): the "some grantor" fallback goes. A class's own copy stays bare beside archetype copies, and grantors of one family give their common name ("Resist Energy (Draconic Bloodline)"); the rest take overrides. Coordinator, on the user's standing instruction; built by build ticket 02f.
- [Planner UI for fast exploration](issues/13-planner-ui-prototype.md): the levelling trail (amended 2026-11-21, the user, from a prototype): a character card, then a trail of level stops whose picks are tappable chips, the next step open in place, one-tap next level, small choices as buttons, open lists with a filter, and automatic folding on phones. Cascade preview, undo, fork and compare stay. Build ticket 07. Before that, ticket 05 built a Timeline with a side picker.
- [Armag's Blade](issues/33-armags-blade.md): stays dropped by its override, because its weapon type isn't in the dump, so no Gear check can judge it. Coordinator, on the user's standing instruction.
- [Mythic classes on offer](issues/34-mythic-classes-on-offer.md): classes and races come from the root progression's lists; the Mythic list leaves out the companions' class and Shard Powers. The user. Amended 2026-11-21 (coordinator, build ticket 05e): every path switch the walk takes is on offer (Gold Dragon included), and the class the story uses to choose the Legend path (`m_MythicLegenFake`) is never offered or taken; Legend reads "Legend".
- [Save files as an oracle](issues/18-save-files-as-an-oracle.md): a `.zks` is a plain ZIP of JSON. The main character's classes, archetypes, picks by level, held facts (rank, source, level, parameter), Mythic classes and ability scores are readable by GUID; choice order and legality aren't. Saves become a second acceptance suite (build ticket 03b) once the user marks which are clean; fixtures hold GUIDs and numbers only. [Findings](research/save-files.md).

## Out of scope

- Picking individual spells (phase 2). Spellbooks count only as prerequisite gates.
- Combat simulation.
- Companions and mercenaries: Builds are the main character only ([Whose builds](issues/01-whose-builds.md)).
- When items become available over the story (a gear timeline).
- Mods.
- [Build review skill](issues/15-what-makes-the-game-easier.md): judging whether a Build is good, with checkpoints, role numbers, traps and reference builds, plus any sheet numbers beyond what the walk computes. It will be built after the full-stack web app, as its own effort.
